# 成片生产流程（从文案到竖屏 mp4）

本流程由 WorkBuddy 在本环境执行，配音除外（用户侧剪映完成）。目标产物：竖屏 720×1280 MP4，约 60–110 秒，含氛围画面 + 逐句字幕 + 歌词卡 + 轻 BGM。

## 一、环境准备（首次）

- 使用 managed Python：`C:/Users/LYY/.workbuddy/binaries/python/versions/3.13.12/python.exe`
- 建 venv：`...python.exe -m venv C:/Users/LYY/.workbuddy/binaries/python/envs/default`
- 装包：`pip install pillow moviepy imageio-ffmpeg`（**不要**依赖系统 ImageMagick，`TextClip` 易缺依赖，字幕一律用 PIL 渲染 PNG 再叠加）
- ffmpeg：无需系统安装，`imageio-ffmpeg` 提供后端。

## 二、配音对接（用户侧，必读）

- 用户在剪映 App「文本朗读」粘贴整段文案 → 选温柔女声（深夜/轻语类）→ 导出 mp3（建议 1.0–1.1x）。
- 用户将 mp3 交回本环境后，拷到项目 `assets/audio/` 重命名为 `capcut_voice.mp3`。
- **不要**尝试在本环境自动生成配音：实测微软 edge_tts / Google gTTS 被网络策略拦截（`NoAudioReceived`）；本机离线语音（pyttsx3 / System.Speech）在无音频设备的沙箱会话中会卡死。**剪映文本朗读是当前唯一稳定方案。**

## 三、画面生成（ImageGen）

为每段（约 5–8 段）生成 1 张竖屏氛围图，风格统一：暖橘 + 深蓝夜色、电影感、柔焦、无文字、9:16。示例提示词模板（换意象即可）：
- 钩子/人设：`a cozy desk with warm lamp at night, intimate late-night radio host, deep blue tones, soft bokeh, no text, 9:16`
- 怀念：`warm afternoon sunlight through tree leaves, golden light spots, nostalgic, blurred figure, no text, 9:16`
- 心动：`after-rain street at golden hour, a hand passing a warm cup, tender moment, soft focus, no text, 9:16`
- 怅然：`night city crowd blurred motion, lonely silhouette walking away, cold blue, longing, no text, 9:16`
- 互动：`warm glowing halo in deep night blue, minimalist, cozy, negative space for text, no text, 9:16`

输出尺寸用 `1024x1536`（即 9:16），存 `assets/backgrounds/`。

## 四、字幕 / 歌词卡渲染（PIL，绕开 ImageMagick）

- 字幕：用 PIL 渲染透明 PNG，深色半透明底条 + 白字（或深蓝底 + 白字），避免 `moviepy.TextClip`。
- 歌词卡：深蓝底 + 一句大字歌词 + 右下角歌手署名（如「赵雷《程艾影》」），干净珍藏感。**卡上大字居中、署名在 76% 高度处**，字幕条需避开卡片时段（歌词句出现时只显卡，解释句配字幕）。
- 栏目卡：结尾「歌词里的心事 · 民谣翻译官」统一模板。

## 五、合成脚本要点（moviepy）

- 背景图做 Ken Burns 缓慢推拉（缩放 1.0→1.08 + 轻微平移），每段时长 = 该段配音时长。
- **转场用交叉溶解**：`from moviepy.video.fx import CrossFadeIn`，下一段 `.with_effects([CrossFadeIn(0.6)])`，实现真溶解（已验证中点像素为红蓝各半，非淡黑）。
- 字幕/歌词卡用 `CompositeVideoClip` 按时间区间叠加。
- BGM：叠一层极低音量（≈0.08）的 A 大调钢琴 pad（可用合成或免版权音源），不抢人声。
- 输出：`720x1280`，`codec='libx264'`，`audio_codec='aac'`。

## 六、字幕时间轴校准（关键，避免"字幕跟说话对不上"）

TTS/转写服务不稳时，用**静音检测 + 标点权重**强制对齐：
1. 用 ffmpeg 提取配音为非静音区间，得到停顿点时间戳。
2. 把文案按标点（，。？！）切成句子，句子数与停顿数应近似相等。
3. 用动态规划把每个句子边界单调匹配到最近的真实停顿时间戳（合并 <0.45s 的碎静音，防止长停顿被切碎）。
4. 字幕区间 = [句首时间戳, 句尾时间戳]，严格跟着配音走，避免累积漂移。
5. 歌词卡只在"念到该歌词句"的子区间出现（精确到句），不与解释句字幕重叠。

## 七、输出规范

- 文件名：`第N期_歌曲名_成片.mp4`，存 `assets/`。
- 竖屏 720×1280，时长以配音实际长度为准（剪映 1.0x 约 70–110s）。
- 交付后用 ffmpeg 抽 8–10 张关键帧自查：钩子字幕、图文对应、歌词卡、栏目卡收尾是否正常。

## 八、已知坑清单（务必避开）

- ❌ 在线 TTS（edge_tts / gTTS）：网络拦截，不可用。
- ❌ 本机离线语音（pyttsx3 / System.Speech）：沙箱无音频设备会卡死；若必须用，逐段独立子进程 + 超时重试可临时凑齐，但不稳。
- ❌ `moviepy.TextClip`：依赖 ImageMagick，Windows 常缺失，改用 PIL 渲染 PNG。
- ❌ 硬切转场：观感生硬，用 CrossFadeIn 0.6s 溶解。
- ❌ 字幕按"字数比例估算"：TTS 语速不均会累积漂移 → 改用静音检测强制对齐。
- ❌ 昵称同音字：AI 念"笔澜"=bǐ lán（似"比蓝"），字幕保持正确汉字即可，无需改字；但建议用户替换为真实账号名避免混淆。
- ✅ 正确做法：剪映文本朗读导出 mp3 → 本环境 ImageGen 出图 + PIL 字幕 + moviepy 合成。
